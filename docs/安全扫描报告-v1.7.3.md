## 一、发现的问题清单（按风险等级）

| # | 等级 | 问题 | 位置 | 影响 |
| --- | --- | --- | --- | --- |
| 1 | 高 | 通过 `adb backup` / 云备份可导出 AK/SK 与运行日志 | `AndroidManifest.xml`（`allowBackup="true"`） | 拿到备份文件即可提取七牛长期密钥，等于拿到 bucket 完整读写权限 |
| 2 | 高 | 上传 policy 手拼 JSON，文件名含 `"` `\` 换行时结构被破坏 | `QiniuToken.uploadToken()` | 上传失败（凭证失效）；极端情况下改变服务端解析到的字段 |
| 3 | 高 | 扫描目录跟随符号链接，可越过用户选定目录 | `ScanRules.collectFiles()` | 目录内一个指向 `/` 或私密目录的软链，会把目录外文件一并上传到云端 |
| 4 | 中 | OkHttp 4.9.1（CVE-2021-0341）、Okio 2.8.0（CVE-2023-3635） | `app/build.gradle` 传递依赖 | 证书主机名校验缺陷 / GZIP 处理 DoS |
| 5 | 中 | 管理 token 可被重定向带到任意主机；UC 返回主机未校验 | `QiniuBucketApi` | 恶意/异常响应可诱导客户端把管理凭证发往第三方主机 |
| 6 | 中 | 列举响应无大小上限 | `QiniuBucketApi.readAll()` | 异常超大响应导致内存耗尽（OOM） |
| 7 | 中 | 上传结果用固定 `sleep 800ms` 判定 | `UploadService` | 大文件/慢网络下「任务已完成」时上传仍在进行，汇总数据失真；任务可能在文件未传完时结束 |
| 8 | 中 | `uploaded.txt` 读取失败时按空集合继续 | `UploadService.loadUploadedSet()` | 会把全部历史文件重新上传一遍（流量 + 覆盖云端对象） |
| 9 | 中 | 日志字段未转义，文件名/服务端错误可注入换行与 `\|` | `UploadLogger` | 伪造日志记录、污染执行汇总 |
| 10 | 低 | 日志读取一次性把整个文件读进内存 | `UploadLogger.readRecent()` | 长期使用后日志膨胀，读取时卡顿/OOM |
| 11 | 低 | 未显式禁止明文 HTTP | `AndroidManifest.xml` | targetSdk 29 下默认已禁止，缺显式声明（配置意图不明确） |
| 12 | 信息 | 仓库内含公开的 Android 调试密钥 `app/keystore/debug.keystore` | `app/keystore/` | 任何人有私钥；但本项目为个人自用分发，签名一致性优先 |

## 二、已修复项与主要改动

### 1. 凭据与备份（#1）
`AndroidManifest.xml`：`android:allowBackup="true"` → `"false"`。
AK/SK（SharedPreferences）、`uploaded.txt`、`uploads.log`、`exec.log` 不再进入系统备份。

### 2. 上传凭证 policy 转义（#2）
`QiniuToken`：新增 `quoteJson()`（与 `org.json` 必要规则一致：`"` `\` `\b\f\n\r\t` 与控制字符转义，
控制字符输出 `\uXXXX`），policy 由字符串拼接改为 `"scope":` + `quoteJson(scope)` + `,"deadline":`。
普通文件名输出字节不变，不影响历史凭证。

### 3. 路径穿越（#3）
`ScanRules`：
- 以所选目录的 `getCanonicalFile()` 为边界，逐个条目先校验真实目标再判断 `isDirectory()/isFile()`
- `isWithinRoot()` 带分隔符边界比较，`root2` 不会被误判为 `root` 子目录
- 已访问目录 canonical 路径去重，同时阻断符号链接环
- 保留原始 `File` 对象入队，`uploaded.txt` 历史记录与云端相对目录结构不变

### 4. 依赖升级（#4）
`app/build.gradle` 显式声明 `okhttp:4.12.0`、`okio:3.6.0`，
解析结果确认：`okhttp 4.9.1 -> 4.12.0`、`okio 2.8.0 -> 3.6.0`（`gradle :app:dependencies`）。

### 5. 网络层（#5 #6）
`QiniuBucketApi`：
- `setInstanceFollowRedirects(false)`：管理 token 只对当前主机签名，不再跟随 3xx
- `isTrustedRsfHost()`：UC 返回的区域主机必须匹配 `qbox.me / qiniuio.com / qiniucn.com / qiniu.com / qiniuapi.com`，
  带点后缀边界（拒绝 `evilqbox.me`、`rsf.qbox.me.evil.example`），且必须是纯主机名（拒绝含 `://`、`@`、`:` 的输入）
- `MAX_RESPONSE_BYTES = 8MB`，超限抛 `IOException`（不再静默返回空串）
- connection 统一在 `finally` 中 `disconnect()`

### 6. 上传流程正确性（#7 #8）
`UploadService`：
- 每个文件用 `CountDownLatch(1)` 等回调 `countDown()`，`await(30 分钟)` 后超时按失败处理，
  再保留 800ms 请求间隔；超时/中断都会写日志，不会无限挂起后台线程
- `loadUploadedSet()` 返回 `boolean`，读取失败时日志记一条并**中止本次任务**（`logExecution(0,1,0)`）
- `saveUploadedPath()` 返回 `boolean`，写失败时日志告警「重启后可能重复上传」
- `QiniuUploader` 的 `put()`/签票同步异常统一转成 `onFail` 回调，保证等待方一定能结束

### 7. 日志安全（#9 #10）
`UploadLogger`：
- `field()` 转义 `\`、`\r`、`\n`、`|`，单字段截断 4096 字符
- `readRecent()` 改为 `LinkedList` 滑动窗口，只保留末尾 N 行再倒序，内存恒定

### 8. 配置（#11）
`AndroidManifest.xml` 增加 `android:usesCleartextTraffic="false"`。

### 9. 附带修正
`QiniuUploader`：文件存在性判断收紧为「存在且是普通文件」；
日志里的访问 URL 改用 `Uri.encode(key, "/")`，空格/`#`/`?` 不再产生错误链接。

## 四、仍需人工确认的风险

1. **调试密钥入库**（信息级，刻意保留）
   `app/keystore/debug.keystore` 是公开的 Android 默认调试密钥（别名 `androiddebugkey`，口令 `android`）。
   入库是为了让 Gitee / GitHub / 本地各渠道安装包签名一致、可互相覆盖升级。
   代价：任何人可伪造「同签名」APK。若未来要上架应用商店或对外分发，应改用私有密钥，
   并接受一次「必须卸载重装」的断档。

2. **targetSdk 仍为 29**（信息级，刻意保留）
   为兼容 `preserveLegacyExternalStorage` 的全盘目录访问（Android 11+ 分区存储会限制扫描范围）。
   带来的间接影响：无法声明 `dataExtractionRules`（API 31+），`allowBackup=false` 在旧模型下生效即可；
   若跟进 Google Play 的 targetSdk 要求，需要重新设计存储权限方案（SAF 或 MediaStore）。

3. **AK/SK 明文存于 SharedPreferences**（低）
   应用私有目录 + `allowBackup=false` 已挡住常规提取路径，但 root 设备仍可读取。
   若需更强保护，可引入 `androidx.security:security-crypto`（EncryptedSharedPreferences）；
   本次未做，因为会增加依赖体积且需要 Keystore 兼容性验证，属独立改造。

4. **`BootReceiver` 为 `exported="true"`**（可接受）
   Android 的 `BOOT_COMPLETED` 属受保护广播，仅系统可发送，第三方应用无法伪造。
   若后续新增自定义 action，必须同步改为 `exported="false"` 并加权限校验。

5. **依赖漏洞库为静态核对**（低）
   本次依据公开 CVE 与官方发布说明判断 OkHttp / Okio 版本，未接入 SCA 工具（无联网授权）。
   建议后续在 CI 加一步依赖检查（如 OWASP Dependency-Check 或 GitHub Dependabot）。

6. **云端对象可被匿名读取的风险在服务端**（提示）
   App 侧只负责上传；bucket 是否为「公开空间」、是否开启 Referer/时间戳防盗链，
   由七牛控制台配置决定，代码无法兜底。建议对私密数据使用私有空间 + 下载凭证。
