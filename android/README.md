# S3FileSync（文件定时同步）

[![Build APK](https://github.com/frwuc/S3FileSync/actions/workflows/android-build.yml/badge.svg)](https://github.com/frwuc/S3FileSync/actions/workflows/android-build.yml)
[![Gitee](https://img.shields.io/badge/Gitee-frwuc%2Fs3--fileuploader-C71D23.svg)](https://gitee.com/frwuc/S3FileSync)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

一款开源的 **Android 文件同步工具**。按设定的时间自动补齐手机目录与你的**七牛云**对象存储之间的新增文件，支持 **仅上传 / 仅下载 / 双向同步** 三种方向，扫描含子文件夹、不限文件类型。

**两端文件名始终与原件一致**——上传不加时间戳，下载不加任何前缀，云端和手机里看到的是同一个名字。无需人工干预：设好时间点和方向，App 每天到点自动同步新增文件。

---

## ✨ 功能特性

- 🔁 **三种同步方向**：仅上传（本地 → 云端）、仅下载（云端 → 本地）、双向（两端新增互相补齐）。设置里一键切换，定时任务 / 打开 App 自动同步 / 手动「立即同步」都按当前方向执行
- ✏️ **文件名原样保留**：上传的云端 key 与下载落盘的文件名都与原件完全一致，**不加时间戳、不加任何前缀**；只保留相对子目录结构。上传与下载共用同一套命名，双向同步不会来回产生副本，也不会覆盖已存在的目标文件
- ⏰ **定时自动同步**：可设置多个时间点（如 10:00、19:00），到点自动扫描并同步新增文件
- ☁️ **七牛云存储**：文件同步到自己的七牛云 bucket，安全可控、容量充足
- 📁 **本地目录可选**：内置文件夹浏览器，逐级进入 / 返回上级挑目录，也可下拉选常用目录或手动输入路径；上传时它是扫描源，下载时它是落盘目标
- 📄 **不限文件类型**：图片、文档、压缩包、视频都同步；子文件夹递归扫描，两端保留目录结构
- 🗂️ **云端目录可选**：内置云端目录浏览器，实时列举 bucket 下的文件夹逐级选择，无需手打 key 前缀
- 👀 **两端内容可浏览**：本地文件夹与云端目录内的文件都能直接查看（大小 + 修改时间）；**默认按时间新到旧排序**，也支持名称 / 时间升降序，排序方式可在「设置」里固定
- 🔍 **文件内容可预览**：**点文件直接预览**——图片 App 内即可查看；文本（txt/log/md/json/代码等）App 内滚动阅读、可选中复制、一键复制全部；PDF / Word / 视频等交给系统应用打开。云端文件先经空间访问域名拉取再同样展示（私有空间自动附加下载凭证）
- 🗑 **文件可删除**：长按文件弹操作单做删除——本地文件删除后列表即时刷新；云端文件走七牛管理接口真删（双重确认，删除不可恢复）
- 🧭 **定时任务排查助手**：定时到点却没同步？「同步任务」 / 「设置」页一键体检（存储权限、电池优化白名单、精确闹钟权限、通知权限、配置完整性与下次触发倒计时），每项可一键授权或跳转设置；按机型识别小米 / vivo / OPPO / 华为 / 荣耀 / 三星 / 魅族，尽量直跳厂商「自启动管理」页，跳不了则给文字指引；内置「1 分钟后实测一次」验证整条链路
- 🔁 **双端增量**：上传过的本地路径、下载过的云端 key 分别记录，互不重复传输；双向时两端记录互相标记，避免「刚传上去又拉回来」
- 🔐 **本地签发凭证**：内置上传凭证本地签发算法，无需自建服务器
- 🌐 **开机自启**：支持开机自动恢复定时任务，重启不丢配置
- 🔋 **电池白名单引导**：一键引导加入电池优化白名单，避免后台被系统杀死（vivo/OPPO 等国产 ROM 必做）
- 🎨 **五页签界面**：同步任务 / 执行记录 / 日志记录 / 设置 / 关于，入口、标题与内容一一对应
- 🚀 **打开即同步（可选，默认关闭）**：开启后启动 App 首次进入界面即按当前方向自动执行一次，旋转屏幕 / 切后台回来不会重复触发

## 🔄 工作原理

```
                 ┌─ 仅上传 ─→ 递归扫描本地目录 → 过滤已上传 → 上传（key 与本地同名）
[定时唤醒 App] ──┼─ 仅下载 ─→ 递归列举云端目录 → 过滤已下载 → 下载（落盘与云端同名）
                 └─ 双向   ─→ 先上传再下载，两端新增互相补齐
                                  ↓
        两端各有增量记录（uploaded.txt / downloaded.txt），已同步的下次跳过
```

App 通过 **AlarmManager** 在设定时间点唤醒前台服务，按配置的同步方向执行：

- **仅上传**：递归扫描配置的本地目录（不限文件类型），把尚未上传过的文件传到七牛云。云端 key = `云端目录/相对子目录/原文件名`。
- **仅下载**：不带 delimiter 递归列举云端目录下的所有对象，把尚未下载过的按相同相对目录写回本地目录。落盘路径 = `本地目录/相对子目录/云端原文件名`。
- **双向**：先上传再下载。上传成功时把该 key 记入「已下载」，下载成功时把该本地路径记入「已上传」，因此不会来回重复传输。

无论哪种方向都**不覆盖已存在的目标文件**：下载时本地已有同名文件就跳过，上传时同名 key 会被覆盖为本次本地版本（这也是去掉时间戳前缀后的预期行为，见下方 FAQ）。

## 🧭 界面结构（底部 5 个页签）

| 页签 | 标题 | 内容 |
|------|------|------|
| 同步任务 | ⚡ 同步任务 | 当前配置摘要（Bucket / 本地目录 / 云端目录 / 定时时间 / **同步方向** / **浏览排序**）+ 立即同步 + 运行状态 + 本地 / 云端内容浏览 |
| 执行记录 | 🗂 执行记录 | **每次任务**的触发时间与结果汇总（成功 / 失败 / 跳过），双向同步时上传与下载各记一条，顶部带累计统计卡片 |
| 日志记录 | 📄 日志记录 | **每个文件**的同步明细（上传看云端 key 与访问地址，下载看本地落盘路径），成功 / 失败用颜色区分 |
| 设置 | 设置 | 七牛云账号、本地目录、定时时间三个可折叠分区 + **同步方向** + **浏览排序方式** + 打开 App 自动同步开关 + 电池白名单 + 定时任务排查助手 |
| 关于 | 关于 | 版本号、开源仓库、联系邮箱、隐私说明 |

「执行记录」与「日志记录」分别对应 `exec.log` 与 `uploads.log`，两页各自独立清空，互不影响。

## 🚀 快速开始

### 方式一：下载现成 APK

- **GitHub Releases**：<https://github.com/frwuc/S3FileSync/releases>（附件 `S3FileSync-<版本号>.apk`）
- **Gitee Releases（国内推荐）**：<https://gitee.com/frwuc/S3FileSync/releases>（附件 `S3FileSync-<版本号>.apk`，无需登录）
- 也可从 **[Actions](https://github.com/frwuc/S3FileSync/actions)** 最新一次成功构建（绿色 ✅）的 **Artifacts** 里下载 `S3FileSync` 压缩包，解压即得 APK

> ⚠️ 附件用仓库内的固定调试密钥签名（`app/keystore/debug.keystore`），只用于个人自测；
> 因为本地与 CI 用同一把钥匙，两个渠道下载的包可以互相覆盖安装。如需正式发布请自行配置签名出 Release 包。

> 📦 两个仓库的代码与版本保持一致：`main` 分支与 `v*` 标签同时推送到 GitHub 与 Gitee，
> 打标签后 CI 会自动构建并创建带 APK 的 Release。

### 方式二：自己构建

```bash
# Gitee（国内推荐）
git clone https://gitee.com/frwuc/S3FileSync.git
# 或 GitHub
git clone https://github.com/frwuc/S3FileSync.git
cd S3FileSync
gradle assembleRelease     # R8 压缩 + 资源收缩，约 3.5MB，已签名可直接安装
# 产物：app/build/outputs/apk/release/S3FileSync-<版本号>.apk（如 S3FileSync-1.9.0.apk）

# 需要断点调试时用 debug 包（不混淆，约 7.5MB）
gradle assembleDebug

# 用 x86 模拟器调试时，需要把 x86 ABI 一起打进去
gradle assembleDebug -PwithX86=true
```

> 体积主要来自七牛 SDK 传递依赖的 conscrypt native 库（arm64 + armv7 约 1.4MB）。
> x86 / x86_64 的 so 默认不打进包，需要模拟器时才用 `-PwithX86=true`。

也可直接用 GitHub Actions 在线构建（推送代码即自动触发）。

## ⚙️ 配置说明

安装后打开 App，按下面几步配置：

### ① 七牛云配置

| 字段 | 说明 |
|------|------|
| **AccessKey (AK)** | 七牛云账号的 AccessKey |
| **SecretKey (SK)** | 七牛云账号的 SecretKey |
| **Bucket 空间名称** | 七牛云对象存储的空间名，如 `my-bucket` |
| **访问域名** | 仅上传时可留默认 `https://z0.qbox.me`（上传由 SDK 自动探测区域）；**要用「仅下载 / 双向 / 云端预览」，必须填空间绑定的访问域名**（控制台 → 空间设置 → 域名管理，可填测试域名），否则下载会 404/403 |
| **云端目录** | 同步到 bucket 下的哪个目录，如 `daka_files`；留空放根目录。上传时它是目标前缀，下载时它是来源前缀。点 **「📂 浏览云端目录并选择」** 可实时列出 bucket 内的文件夹，逐级点进去后一键选中 |

> AK/SK 获取：登录 [七牛云控制台](https://portal.qiniu.com/) → 个人中心 → 密钥管理。
> Bucket 创建：对象存储 Kodo → 新建空间。
> 云端浏览走七牛 `list` 接口，用填写的 AK/SK 在本地签发管理凭证，**只读、不产生存储费用**。
> 签名优先使用七牛现行官方 SDK 的「Qiniu」方案（`QiniuMacAuth`），收到 401 会自动回退旧版「QBox」
> 签名重试一次，新老账号都能用；列举主机由 UC 接口按 bucket 所属区域自动解析，不写死华东节点。
>
> 当前版本走七牛原生 SDK，不使用 S3 协议域名；若以后改用 AWS S3 协议对接，
> 官方服务域名 / Region ID / S3 空间名对照见 [docs/七牛云S3兼容-服务域名.md](docs/七牛云S3兼容-服务域名.md)。

### ② 本地文件目录

- 点 **「📂 浏览本地文件夹并选择」** 打开文件夹浏览器：逐级进入子文件夹、`⬆ 上级` 返回、底部一键「选择此文件夹」
- **下拉选择**常用目录：`DCIM/Screenshots`、`Pictures/Screenshots`、`DCIM/Camera`、`Pictures`
- 或选 **"自定义路径..."** 手动输入任意绝对路径（如 `/sdcard/DCIM/Camera`）
- 上传时该目录（含子文件夹，深度上限 16 层）会被递归扫描，云端 key 保留相对目录结构；下载时它是落盘根目录，云端的相对子目录会照样还原

### ③ 定时同步时间

- 点 **"＋ 添加时间点"** 添加多个时间（格式 `HH:mm`，如 `10:00`、`19:00`）
- 到点按当前同步方向自动执行一次

配置完成后点 **"保存配置并启用定时任务"** 即可。

### ④ 同步方向与浏览排序（设置页）

- **同步方向**：`仅上传` / `仅下载` / `双向同步`。默认「仅上传」（老版本升级后行为不变）。切换后立即生效，不需要点「保存配置」
- **浏览排序方式**：`时间 ↓`（新到旧，**默认**）/ `时间 ↑` / `名称 ↑` / `名称 ↓`。作用于本地文件夹与云端目录的浏览列表，切换后立即保存
- 在浏览器里点顶部的 `名称` / `时间` 按钮临时切换排序，也会同步更新这里，下次打开任意浏览器继续沿用
- 不管怎么排，**文件夹始终排在文件前面**，避免翻找时上下跳

> ⚠️ 选「仅下载」或「双向」时，请确认 ① 里的域名填的是**空间绑定的访问域名**而不是上传域名，
> 并且本地目录有写权限（`targetSdk 29` 走旧存储模型，需授予存储权限）。

### ⑤ 打开 App 时自动同步

- **默认关闭**。关闭时打开 App 不会发起任何同步，只有定时任务和手动点击「立即同步」会触发。
- 打开后，每次启动 App 首次进入主界面会按当前方向自动执行一次；**只在进程启动后的首次进入触发**，
  旋转屏幕、切后台再回来、切换页签都不会重复触发。
- 触发前会检查：七牛云 AK/SK/Bucket 与本地目录是否配置完整、是否已授予存储权限、是否已有任务在跑；
  任一项不满足则跳过，并用提示说明原因（不会强行同步）。
- 开关切换后立即保存（不需要点「保存配置」），下次打开 App 生效。

> 💡 **vivo / OPPO / 小米** 等机型请务必点 **"设置电池优化白名单"**，否则后台定时任务容易被系统杀掉。

### ⑥ 浏览同步文件夹内容

配置页与「同步任务」页都提供浏览入口，打开后是同一套浏览器：

- **本地文件夹**：列出当前文件夹下的子文件夹与文件，显示文件大小与修改时间；点文件夹进入，`⬆ 上级` 返回
- **云端目录**：通过七牛 `list` 接口实时列举 bucket 内该目录下的子目录与对象（含大小与上传时间）；
  主机按 bucket 所属区域自动解析，签名用现行「Qiniu」方案（401 自动回退旧版「QBox」）
- **排序**：默认 **时间 ↓（新到旧）**；顶部 `名称` / `时间` 两个按钮，点一下切换升 / 降序
  （`名称 ↑` `名称 ↓` `时间 ↑` `时间 ↓`）；文件夹始终排在文件前面。默认与后续排序方式都可在「设置」里配置
- **看全文件名**：文件名最多显示 3 行（不再单行中间省略）；仍超长的，点该文件弹出「文件信息」，
  含完整文件名、完整路径、大小与修改时间，正文可长按选中，也可点「复制文件名」
- 底部 **「✓ 选择此文件夹」** 会把当前目录写回配置（本地取绝对路径，云端取 key 前缀、根目录为空），
  在同步页使用时立即生效，在设置页使用时还需点一次「保存配置」

## 🔒 隐私与安全

- 你的 **AK/SK 仅保存在手机本地**（SharedPreferences，`MODE_PRIVATE`），不会上传到任何第三方服务器
- 文件只在**你自己配置的七牛云 bucket** 与本地目录之间传输，不经手任何中间服务器
- 开源透明，所有逻辑可审计

### 已实施的安全措施（v1.7.3 起）

| 面向 | 措施 |
| --- | --- |
| 凭据留存 | `android:allowBackup="false"`，AK/SK 与 `uploaded.txt`、`downloaded.txt`、日志不会被系统备份带出设备 |
| 传输 | 全部接口走 HTTPS；显式 `usesCleartextTraffic="false"`，不允许明文回落到 HTTP |
| 上传凭证 | policy 做 JSON 转义，文件名含引号 / 反斜杠 / 换行也不会破坏凭证结构 |
| 列举接口 | 管理 token 只对当前主机签名，禁止自动跟随重定向；区域主机限定七牛官方域名白名单；响应体上限 8 MB |
| 路径穿越 | 本地扫描以所选目录的 canonical 路径为边界，指向目录外的符号链接一律跳过（并阻断链接环）；**下载时云端 key 逐段校验，拒绝 `..`、绝对路径、隐藏项与非法分隔符，并复核 canonical 路径仍在本地根目录内** |
| 下载落盘 | 先写 `文件名.part` 临时文件，完整成功后才 rename 成目标文件，中断不会留下半个假文件；本地已存在的目标文件不覆盖 |
| 日志注入 | 文件名 / 服务端错误写日志前转义 `\`、换行与 `\|`，单字段截断 4 KB |
| 依赖 | OkHttp 4.12.0、Okio 3.6.0（修复 CVE-2021-0341、CVE-2023-3635） |

## ❓ 常见问题

**Q：三种同步方向怎么选？**
A：「仅上传」适合手机拍照/截图单向备份到云端（也是默认值）；「仅下载」适合把云端已有资料拉回手机；「双向」适合两台设备通过同一个 bucket 互相同步。三种方向都只传增量，文件名两端一致。注意「双向」不会做冲突合并或删除传播——它只补齐两端**新增**的文件，任一端删除文件不会同步删掉另一端。

**Q：文件名真的和原件一模一样吗？以前不是带时间戳吗？**
A：v1.9.0 起不再加 `时间戳_` 前缀。上传后云端路径为 `云端目录/相对子目录/原文件名`，下载落盘为 `本地目录/相对子目录/云端原文件名`。不同子目录下的同名文件靠相对目录区分，不会串。**升级提示**：旧版本已上传的带时间戳文件仍留在云端、不会被自动改名或删除；升级后新上传的文件用新命名，云端可能同时存在新旧两份，需要的话可在云端浏览器里长按删除旧文件。

**Q：到点没同步 / 定时任务不触发？**
A：按顺序排查：
1. **v1.8.0 之前装的老版本有已知 Bug**：闹钟每个时间点只在「保存配置 / 开机」后触发一次，
   第二天起就静默失效——请先升级到 v1.8.0 及以上（v1.8.0 起每次触发后会自动把下一次排上）；
2. 国产 ROM（vivo/OPPO/小米/华为/荣耀）后台管控严格：打开 App 里新加的
   **「⏰ 定时不触发？点我逐项排查」**（同步任务页 / 设置页两个入口都有），
   按行体检并一键处理——电池优化白名单、自启动（会尽量直跳厂商设置页）、存储权限、
   精确闹钟权限（Android 12+）；
3. 检查完再点助手最后一行的 **「1 分钟后测试」**：一分钟内若弹通知并开始执行，
   说明链路已通；没反应说明手机仍未放行，按文字指引补设置。

**Q：下载 / 双向同步提示下载失败？**
A：九成是「访问域名」没填对。上传走七牛 SDK 自动探测区域，用 `z0.qbox.me` 这类**上传域名**也能成功；但下载必须用**空间绑定的访问域名**（控制台 → 空间设置 → 域名管理，可填测试域名）。私有空间不用手动开关，App 会在公开 GET 被 401/403 拒绝时自动附加 10 分钟有效期的下载凭证重试。

**Q：到点自动同步，需要提前打开 App 吗？会常驻后台吗？**
A：**不用手动打开**。到点后系统会把 App 的后台进程（前台服务）自动唤醒，无界面地完成同步全过程，完成后服务自己退出，**不会在屏幕上弹出 App 界面，也不是常驻后台**（平时不占进程）。前提只有一条：App 已安装并保存过配置，且**自启动 / 电池白名单已放行**——没放行时，系统会在锁屏期间拒绝唤醒它（排查助手即为此设）。

### 📱 vivo（OriginOS 6）保活五步操作（X200 Pro 实测）

以下步骤按优先级从高到低排，照着做完基本能保证定时任务 App 不被系统杀掉。

1. **🔒 后台加锁（最基础，必做）**：打开本应用 → 底部上滑停顿调出多任务后台 →
   找到本应用卡片**按住往下滑一下** → 卡片右上角出现 🔒 即锁定成功。
   防止一键清理或系统自动清理时误杀进程。
2. **🔋 允许后台高耗电（核心开关）**：设置 → 电池 → **后台耗电管理** → 本应用 →
   改为**允许后台高耗电**。不开的话息屏后很容易被冻结。
3. **🚀 开启自启动（重启/被杀后自动恢复）**：手机管家（原 i管家）→ 应用管理 → 权限管理 →
   **自启动** → 打开本应用开关；点进应用详情把**关联启动**也打开。
4. **🛡️ 加入加速白名单（双重保险）**：手机管家 → 省电管理/电池管理 →
   **后台高耗电 / 加速白名单** → 右上角 ＋ 把本应用加进去，避免深度清理误杀。
5. **🌙 关闭睡眠模式冻结（夜间长续航场景）**：设置 → 电池 → 更多设置/睡眠模式 →
   **智能后台冻结 / 睡眠待机优化** → 把本应用加入**不受限制名单**。
   定时在凌晨执行的一定要做，不然睡眠模式会把后台全冻住。

**验证方法**：打开 App 后按 Home 键回桌面 → 等 10 分钟再从后台点开 →
直接回到之前的页面（没有重启白屏/loading）即保活成功。

> ⚠️ 小提示：不要开「省电模式」或「超级省电」，这两个模式会强制限制后台活动，保活设置会失效。
> 另外如果哪天手动上滑清理了本应用（加锁的卡片一次上滑清不掉），被清理后期间到点的闹钟会被
> 拒收——**回 App 打开一次即可**（启动时自动重排下一次闹钟）。

**Q：怎么预览 / 删除文件？**
A：本地与云端浏览列表里点任意文件，弹出操作单：**预览内容**（图片与文本 App 内直接看，
其它类型交给系统应用；云端文件经空间访问域名拉取，私有空间自动附加下载凭证）、
**删除文件**（本地一步确认；云端两步确认后经七牛管理接口真删，不可恢复）、复制文件名。

**Q：预览云端文件必要条件？**
A：需要在「设置 → 七牛云账号」把**域名一栏填成空间绑定的访问域名**
（七牛控制台 → 空间设置 → 域名管理，可填测试域名）。填的是上传域名（如 `z0.qbox.me`）
时列表可用，但预览下载会失败。

**Q：同步后的文件在哪里？**
A：在七牛云控制台 → 对象存储 → 你的 bucket → 你设置的**云端目录**下，文件名与手机上的原件完全一致；若文件来自子文件夹，会保留相对目录：`云端目录/子文件夹/原文件名`。下载则相反：文件落在本地目录下，路径为 `本地目录/相对子目录/云端原文件名`。

**Q：可以只同步某个文件夹的文件吗？**
A：可以。在"本地文件目录"点「📂 浏览…并选择」或填该文件夹的绝对路径；云端一侧同理用「云端目录」限定前缀。两侧都支持逐级浏览选择。

**Q：能同步图片以外的文件吗（PDF / Word / 压缩包 / 视频）？**
A：能。不限文件类型，目录下有什么同步什么；下载走流式写盘，大视频也不会占满内存。子文件夹也会递归，两端按 `云端目录/子文件夹/原文件名` 与 `本地目录/子文件夹/原文件名` 对应。只跳过以 `.` 开头的隐藏项和 0 字节的空文件。

**Q：已同步的文件会被重复传输吗？**
A：不会。上传记录存本地文件的绝对路径（`uploaded.txt`），下载记录存云端 key（`downloaded.txt`），重复的自动跳过。双向同步时还会互相标记：刚上传的文件不会被下载回来，刚下载的文件也不会被传回去。注意：因为文件名不再带时间戳，**同一相对路径下的同名文件在上传时会覆盖云端同名对象**；若本地文件被修改后想重新上传，需要改文件名或清掉 `uploaded.txt` 里对应记录。

**Q：浏览列表默认按什么排序？能改吗？**
A：默认 **时间 ↓（新到旧）**，符合手机相册的直觉。可在「设置 → 浏览排序方式」改成时间 ↑ / 名称 ↑ / 名称 ↓，切换后立即保存；在浏览器里点顶部 `名称` / `时间` 按钮也会同步更新该设置。文件夹始终排在文件前面。

**Q：浏览云端目录提示 401 / `bad token`，但上传是正常的？**
A：上传凭证与管理凭证是两套签名体系，上传正常不代表管理接口也通。请依次检查：
① AK/SK 是否在 [七牛控制台 → 密钥管理](https://portal.qiniu.com/) 仍有效（换过密钥要重新粘贴保存）；
② Bucket 名称是否与账号下的空间完全一致；
③ 确认装的是最新版本——旧版只用「QBox」老签名，较新的七牛账号会拒绝，v1.6.3 起已改为「Qiniu」新签名并自动回退兼容。
错误提示里会带上七牛服务器的原始返回，便于进一步定位。

**Q：需要自建服务器吗？**
A：不需要。上传凭证、管理凭证与私有下载凭证都由 App 本地签发，直连七牛云。
